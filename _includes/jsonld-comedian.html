{%- comment -%} Person + ProfilePage JSON-LD partial for /comedians//. Consumed by: _includes/default/head.liquid — included only when page.layout == 'comedian', so it never fires on shows, the index, or noindex pages (e.g. /lineup/). Why ProfilePage→mainEntity:Person — this is exactly Google's documented shape for "a page that is about one person". The `sameAs` array is the machine- readable router to the comedian's other online presences (Knowledge-Graph entity reconciliation). The two @ids are DELIBERATELY distinct to avoid a same-@id/different-@type collision: ProfilePage @id = the page URL (the page IS the profile page) Person @id = the page URL + #person (the entity the page is about) memberOf points at the homepage Organization node (@id site.url/#organization, set in jsonld-organization.html) so person↔club links up in the graph. ProfilePage MUST be a ROOT node — Google's spec says so, and it is the thing this file exists to deliver. It nearly wasn't: jekyll-seo-tag emits, for any page it types BlogPosting, a stub `"mainEntityOfPage": {"@type":"WebPage","@id": }` whose @id is exactly the @id below. Google merges by @id, so our ProfilePage got absorbed as a CHILD of that BlogPosting and Search Console reported "Invalid object type for field ''" on every comedian page. The stub is switched off in _config.yml (`defaults` → `type: comedians` → `seo.type: WebPage`) — do not remove that entry, and do not "simplify" the @id here to a fragment to route around it. script/check-site.rb asserts both halves.
